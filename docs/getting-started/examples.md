# Examples

Examples are executable documentation when they are kept synchronized with the repository.

## How to read an example

For each example, distinguish:

1. what the example is intended to demonstrate;
2. what code is actually executed;
3. which dependencies are real and which are simulated;
4. what tests cover the behavior;
5. what evidence status the example supports.

## Evidence labels

Examples should use the repository verification vocabulary where relevant:

- `SPECIFIED`
- `SCAFFOLDED`
- `SIMULATED`
- `IMPLEMENTED`
- `TESTED`
- `BENCHMARKED`
- `INTEGRATION-TESTED`
- `HARDWARE-VALIDATED`

An example should never be presented as a production capability solely because it compiles or produces plausible output.
